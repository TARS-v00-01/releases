    xWalk Developer Notes Wiki¶

    xWalk-rpi5-tool/doc-tool/wiki.sh builds these Markdown collections as a searchable Material for MkDocs website. It provides local-development, college-server, and GitHub artifact profiles.

    Run the examples from the repository root. Generated dependencies and HTML remain under the ignored build-devloper-note-wiki directory.

    Local profile¶

    Build the wiki, bind it only to the current computer, and open the default browser:

    xWalk-rpi5-tool/doc-tool/wiki.sh local

    The default URL is http://127.0.0.1:8000/. Press Ctrl-C to stop the local server.

    Serve locally without opening a browser:

    xWalk-rpi5-tool/doc-tool/wiki.sh local --no-open

    Choose another loopback port:

    xWalk-rpi5-tool/doc-tool/wiki.sh local --port 8001

    The local profile rejects non-loopback bind addresses.

    College-server profile¶

    Run this command on the college server:

    xWalk-rpi5-tool/doc-tool/wiki.sh server

    It builds production-style static HTML under build-devloper-note-wiki/server-site, binds to 0.0.0.0:8080, and serves until Ctrl-C is pressed.

    When the college provides a public HTTPS address, include it in the build:

    xWalk-rpi5-tool/doc-tool/wiki.sh server --site-url https://docs.example.edu/xwalk/

    Use another approved port when required:

    xWalk-rpi5-tool/doc-tool/wiki.sh server --port 9000 --site-url https://docs.example.edu/xwalk/

    Binding to 0.0.0.0 listens on every server interface. Worldwide access additionally requires:

    • a public college DNS name or public IP address;
    • firewall and NAT rules that permit the selected port;
    • a TLS certificate and HTTPS reverse proxy, normally Nginx or Apache;
    • college authorization for public hosting; and
    • a persistent service manager if the wiki must survive logout or reboot.

    The built-in Python static server is appropriate for initial verification. Use the college's managed HTTPS web server for production access and point its document root at the generated server-site content.

    GitHub artifact profile¶

    Build the same static documentation artifact used by GitHub Actions:

    xWalk-rpi5-tool/doc-tool/wiki.sh github

    The default site URL embedded in locally generated metadata is:

    https://TARS-v00-01.github.io/releases/

    Open the configured site URL after building:

    xWalk-rpi5-tool/doc-tool/wiki.sh github --open

    This option does not open the local artifact. With Pages disabled, the configured URL may return 404.

    Override the URL when the repository or custom domain changes:

    xWalk-rpi5-tool/doc-tool/wiki.sh github --site-url https://docs.example.org/xwalk/

    The github profile only creates build-devloper-note-wiki/github-site; it never pushes. After an approved Gerrit integration commit is submitted and synchronized to TARS-v00-01/releases/master, the developer-note-pages.yml workflow builds the site once and uploads it as a private GitHub Actions artifact. Authorized organization members can download the artifact from the workflow run. The artifact is retained for 30 days and does not publish a website.

    The current GitHub plan does not support Pages for the private xWalkPiCarAI repository. Do not make the repository public to enable Pages because the integration tree identifies private component revisions. A future Pages deployment requires an approved organization plan, an explicit privacy review, and a reviewed Gerrit change that restores Pages permissions and deployment steps. Until all three conditions are satisfied, a Pages API 404 or plan-related 422 is an expected configuration limitation, not a reason to bypass Gerrit or repository privacy.

    The workflow validates the committed integration metadata without initializing private Gerrit submodules. The developer-note sources are already part of the exact submitted integration commit synchronized to GitHub, so the artifact build requires no Gerrit SSH key, server address, or account variables.

    Optional global organization wiki¶

    A global organization site can use this URL:

    https://tars-v00-01.github.io/

    GitHub requires its repository to be named exactly TARS-v00-01/tars-v00-01.github.io. With the current plan, that repository must be public. An organization Pages site cannot be restricted to organization members, so the complete site and every published asset must be treated as public. Creating the repository is not approved merely by documenting this option, and the global site is not currently configured.

    If a global site is approved, publish only a sanitized documentation set from a separate Gerrit project. Exclude private source, credentials, internal service addresses, restricted architecture details, and links that reveal content unavailable to public readers. Keep all component repositories and the integration repository private.

    The approved flow must remain submit-gated:

    sanitized documentation -> Gerrit review and CI -> Submit -> explicit mirror -> TARS-v00-01/tars-v00-01.github.io -> Pages

    The GitHub repository must not accept normal developer pushes or pull requests as an alternate review path. The Gerrit change log must record the submitted source revision, mirror result, GitHub commit link, and Pages deployment result. A failed deployment is corrected through a new Gerrit review; it is never repaired with a direct GitHub push.

    CI verification¶

    Validate wiki-owned local links, strictly build the GitHub artifact, and validate its homepage, sitemap, search-index JSON, and configured site URL:

    xWalk-rpi5-tool/doc-tool/wiki.sh verify

    This non-serving command is used by Gerrit component CI, integrated Host Quality, and GitHub Host Quality. It does not open a browser, bind a port, or publish the generated artifact.

    Dependency setup¶

    Every profile creates an isolated Python environment when needed. Prepare it without starting a site:

    xWalk-rpi5-tool/doc-tool/wiki.sh setup

    The package pin is in xWalk-rpi5-tool/doc-tool/requirements-wiki.txt. First-time installation requires Python 3, the Python venv module, and package-index access.

    Remove generated files¶

    xWalk-rpi5-tool/doc-tool/wiki.sh clean

    This removes only the validated build-devloper-note-wiki directory. It does not remove source notes.

    Build behavior¶

    • mkdocs.yml enables Material navigation, tables, heading anchors, and local full-text search.
    • Every profile stages a fresh copy of the Markdown source before building or serving it.
    • Links to workspace files outside devloper-note are converted in the staged artifact to GitHub source links for the exact deployed revision. Source Markdown retains its checkout-relative links.
    • Every build cleans stale HTML from its profile-specific site directory.
    • Generated environments and HTML must not be committed.
